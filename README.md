# Подсистема ручного ввода информации (АРМ оператора продаж) на Django

Проект реализует учебную подсистему ручного ввода для АРМ оператора по продажам.
Система разработана на фреймворке Django и демонстрирует:

- интерфейс работы оператора с **клиентами**;
- **подсистему склада** и справочник товаров;
- **оформление заказов** с разными видами продаж (наличные, безнал, кредит, бартер, взаимозачёт);
- автоматический контроль остатков, кредитных лимитов, подсветку и предупреждения;
- формирование **отчёта по заказам клиентов**.

## Структура проекта

- `lab_is/` — Django‑проект.
    - `settings.py` — настройки, включено приложение `sales`.
    - `urls.py` — корневые маршруты, в том числе главная страница `/` и подключение `sales/`.
- `sales/` — приложение АРМ оператора.
    - `models.py` — модели:
        - `Client` — клиент, его счета, кредитный лимит и долг;
        - `Product` — товар, цена и остаток на складе;
        - `Order` — заказ с типом продажи;
        - `OrderItem` — позиция заказа (товар, количество, цена, сумма).
    - `forms.py` — формы:
        - поиск клиента;
        - управление товарами;
        - создание заказа и табличная часть (formset).
    - `views.py` — представления:
        - главная страница;
        - поиск клиента;
        - склад товаров;
        - создание и просмотр заказа;
        - отчёт по заказам клиентов.
    - `urls.py` — маршруты приложения `sales`.
    - `templates/sales/` — HTML‑шаблоны интерфейсов оператора.
    - `static/sales/` — статические файлы (в т.ч. звук предупреждения `warning.mp3`).

## Основные URL

- `/` — главная страница с описанием и ссылками.
- `/sales/clients/search/` — поиск клиента и просмотр его счетов и кредита.
- `/sales/products/` — база товаров / склад.
- `/sales/orders/new/` — создание нового заказа.
- `/sales/orders/<id>/` — просмотр конкретного заказа.
- `/sales/reports/client-orders/` — отчёт по заказам клиентов.

## Локальный запуск (без Docker)

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

python manage.py migrate
python manage.py runserver
```

После запуска проект будет доступен по адресу `http://127.0.0.1:8000/`.

## Запуск в Docker

### 1. Сборка образа

```bash
docker build -t lab_is_app .
```

### 2. Запуск контейнера напрямую

```bash
docker run --rm -it -p 8000:8000 lab_is_app
```

Приложение будет доступно по адресу `http://localhost:8000/`.

### 3. Запуск через docker-compose

```bash
docker-compose up --build
```

Это поднимет сервис `web` c приложением Django, пробросив порт `8000:8000`.

## Файлы конфигурации

- `Dockerfile` — образ приложения Django.
- `docker-compose.yml` — удобный запуск сервиса `web`.
- `.gitignore` — исключения для Git (виртуальное окружение, временные файлы, БД и т.д.).
- `.dockerignore` — исключения при сборке Docker‑образа (не попадают внутрь образа).
