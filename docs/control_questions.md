# Контрольные вопросы по лабораторной работе

## 1. Как устанавливаются и удаляются связи между таблицами?

- **В реляционных БД** связи задаются через **первичные ключи (PRIMARY KEY)** и **внешние ключи (FOREIGN KEY)**.
  - В таблице‑«родителе» есть поле с уникальными значениями (PRIMARY KEY).
  - В таблице‑«потомке» есть поле, которое ссылается на это значение (FOREIGN KEY).
- **Установка связи**:
  - при проектировании — объявить внешние ключи в DDL (CREATE TABLE / ALTER TABLE ... ADD CONSTRAINT ... FOREIGN KEY ...);
  - при работе через ORM (например, Django) — задать поля `ForeignKey`, `OneToOneField`, `ManyToManyField` и выполнить миграции.
- **Удаление связи**:
  - в SQL — через `ALTER TABLE ... DROP CONSTRAINT имя_ограничения`;
  - в ORM — удалить/изменить поле связи в моделях и выполнить миграции, которые уберут ограничение во внешнем ключе.

## 2. Как удалить/установить тип связи?

Тип связи (1:1, 1:M, M:N) определяется **структурой ключей**:

- **1:1** — внешний ключ в одной таблице с уникальным ограничением (`FOREIGN KEY` + `UNIQUE`) или общий первичный ключ.
- **1:M** — первичный ключ в родительской таблице, внешний ключ (без `UNIQUE`) в дочерней таблице.
- **M:N** — создаётся **промежуточная таблица** (таблица связи) с двумя внешними ключами на связанные таблицы.

Чтобы **изменить тип связи**:

1. Проанализировать текущую схему (какие поля являются FK, есть ли `UNIQUE`).
2. Описать новую структуру:
   - например, заменить M:N на 1:M — убрать промежуточную таблицу и добавить FK в одну из таблиц;
   - заменить 1:1 на 1:M — снять `UNIQUE` с внешнего ключа.
3. Выполнить:
   - в SQL — `ALTER TABLE` (добавить/убрать `UNIQUE`, добавить/удалить таблицу связи, изменить FK);
   - в ORM — изменить модели (поля/типы связей), создать и применить миграции, при необходимости перенести данные.

## 3. Как обеспечить целостность данных? Как работают каскадное удаление, добавление?

**Целостность данных** обеспечивается за счёт:

- **Ссылочной целостности** — внешние ключи запрещают:
  - появление «висящих» ссылок (когда в дочерней таблице есть ссылка на несуществующую запись);
  - удаление родительской записи, пока на неё ссылаются дочерние записи (если не разрешено каскадом).
- **Ограничений**: `NOT NULL`, `UNIQUE`, `CHECK`, `DEFAULT`, триггеров.
- **Логики в приложении** — валидации на уровне кода/форм.

**Каскадное удаление (`ON DELETE CASCADE`)**:

- При удалении записи в родительской таблице СУБД **автоматически удаляет все записи** в дочерних таблицах, которые на неё ссылаются.
- Это удобно, когда «потомки» не имеют смысла без «родителя» (например, строки заказа без самого заказа).

**Каскадное обновление (`ON UPDATE CASCADE`)**:

- При изменении значения ключа в родительской таблице СУБД **автоматически обновляет соответствующие внешние ключи** в дочерних таблицах.

**Каскадное добавление** в чистом SQL как правило не выделяется отдельным термином:

- Обычно добавление реализуется логически: сначала создаётся родительская запись, затем — дочерние, которые ссылаются на её ключ.
- В ORM (Django и др.) каскадное создание может выглядеть как сохранение объекта вместе с связанными объектами (например, `order` и его `order_items` в одной транзакции), чтобы данные были согласованными.

## 4. Как создать шаблон ввода телефонного номера в формате +7(000)-000-00-00?

Требования:

- вводится только **10 цифр** (без кода страны, не больше);
- формат: `+7(000)-000-00-00`;
- **буквы вводить нельзя**, скобки/дефисы подставляются автоматически.

Общая идея реализации (на примере веб-формы):

1. **Использовать маску ввода** (input mask) на стороне клиента:
   - через готовую библиотеку (например, Inputmask, Cleave.js и т.п.);
   - либо написать простой обработчик на JavaScript.
2. **Алгоритм работы маски**:
   - слушать событие `input` поля;
   - из введённого значения удалять всё, кроме цифр (`0–9`);
   - обрезать строку максимум до 10 цифр;
   - на основе этих цифр каждый раз формировать строку по шаблону:
     - первая цифра — первая позиция после `+7(`,
     - вторая и третья — следующие позиции внутри скобок,
     - далее подставлять дефисы по маске.
3. **Запрет букв**:
   - при каждом вводе фильтровать все нецифровые символы;
   - дополнительно можно использовать HTML‑атрибуты:
     - `type="tel"`,
     - `pattern="\d{10}"` (для проверки количества цифр),
     - `maxlength` для ограничения длины маски.

Пример упрощённой логики на JS (идея, не привязана к фреймворку):

```javascript
const input = document.getElementById("phone");

input.addEventListener("input", () => {
  let digits = input.value.replace(/\D/g, "").slice(0, 10); // только цифры, не больше 10

  let result = "+7(";
  if (digits.length > 0) result += digits.slice(0, 3);
  if (digits.length >= 3) result += ")";
  if (digits.length > 3) result += "-" + digits.slice(3, 6);
  if (digits.length > 6) result += "-" + digits.slice(6, 8);
  if (digits.length > 8) result += "-" + digits.slice(8, 10);

  input.value = result;
});
```

Таким образом:

- пользователь реально вводит только цифры;
- формат `+7(000)-000-00-00` формируется автоматически;
- буквы и лишние символы отбрасываются при каждом вводе.
