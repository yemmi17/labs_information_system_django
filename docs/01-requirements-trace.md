# Трассировка требований («чёрный» текст ТЗ)

Ниже — как формулировки задания (смысловое содержание основного текста) отображаются в программе.

| Требование (смысл) | Реализация |
|--------------------|------------|
| Мини-CASE для моделирования программ с математической моделью | Пакет `mini_case`: конфигурация цепочки из трёх функций и вычисление значения **y**. |
| Модель **y = F₁(F₂(F₃(x)))** | Функция `evaluate(x, f3, f2, f1)` применяет **f3 → f2 → f1** к **x** (см. `mini_case/evaluate.py`). |
| Набор **Fᵢ**: √x, 1/x, e^x | Идентификаторы `sqrt`, `inv`, `exp`; подписи в интерфейсе «√x», «1/x», «e^x». |
| Последовательное «соединение» функций | В боте три шага выбора: **F₃**, затем **F₂**, затем **F₁** (инлайн-кнопки). |
| Корректные вложенные вычисления | Промежуточное значение передаётся по цепочке; порядок фиксирован математически. |
| Ошибка при выходе за область определения | На каждом шаге перед применением функции выполняется проверка; пользователю возвращается номер шага (1–3), имя функции и пояснение. |

## Уточнение по «шагам»

- **Шаг 1** — применение **F₃** к исходному **x**.
- **Шаг 2** — **F₂** к результату шага 1.
- **Шаг 3** — **F₁** к результату шага 2.

Так сообщения об ошибках однозначно сопоставляются с выбранной пользователем позицией в цепочке.
