# Описание кода: вариант 6 — продажи через кассовый аппарат (Django)

Документ описывает реализацию в каталоге [`cash_register/`](../cash_register/) относительно корня репозитория.

## Назначение

Учёт строк продаж с полями из задания и **расчёт суммы прибыли по каждой группе товаров**. Формула для одной продажи (строки чека):

\[
\text{прибыль} = (\text{цена продажи без скидки} \times \text{количество}) - (\text{цена закупки} \times \text{количество})
\]

Эквивалентно: \((\text{sale\_price} - \text{purchase\_price}) \times \text{quantity}\). Поле **скидка** хранится в данных, но в эту формулу не входит: в расчёте используется номинальная продажная цена без скидки.

## Модели данных (`sales/models.py`)

### `ProductGroup`

- Поле `name` — уникальное наименование группы товаров.
- Используется для нормализации: у каждой продажи одна группа через внешний ключ.

### `Sale`

Соответствие полям задания:

| Поле в коде | Смысл |
|-------------|--------|
| `product_name` | Наименование товара |
| `product_group` | Группа товара (FK на `ProductGroup`) |
| `quantity` | Проданное количество |
| `sale_price` | Продажная цена **за единицу, без скидки** |
| `purchase_price` | Закупочная цена за единицу |
| `discount` | Скидка в процентах (справочно для исходных данных) |

Дополнительно:

- Валидаторы `MinValueValidator` не допускают отрицательных цен и нулевого количества.
- Свойство `line_profit` считает прибыль по одной строке в Python (для списка продаж и админки).

Миграции лежат в `sales/migrations/` (начальная — `0001_initial.py`).

## Обработка: прибыль по группам (`sales/views.py`)

Функция **`profit_by_group`**:

1. Строит выражение прибыли строки через ORM: `ExpressionWrapper((F("sale_price") - F("purchase_price")) * F("quantity"), ...)`.
2. Выполняет запрос: `Sale.objects.values("product_group__name").annotate(total_profit=Sum(line_profit)).order_by(...)`.
3. Считает **общий итог** по всем группам в Python: сумма `total_profit` по строкам результата (с учётом `None`).

Так агрегация выполняется на стороне БД, без выгрузки всех строк для суммирования по группам.

Функция **`sale_list`** выводит все продажи с `select_related("product_group")`, чтобы не делать отдельный запрос на группу для каждой строки.

## Маршруты

- **`config/urls.py`**: `path("", include("sales.urls"))` подключает приложение на корень сайта.
- **`sales/urls.py`**:
  - `""` → `profit_by_group` (имя `profit_by_group`) — отчёт по группам;
  - `"sales/"` → `sale_list` (имя `sale_list`) — таблица исходных продаж.

## Шаблоны (`sales/templates/sales/`)

- `base.html` — общий каркас, навигация на отчёт, список продаж и админку.
- `profit_by_group.html` — таблица «группа — сумма прибыли» и строка «Итого».
- `sale_list.html` — таблица полей продажи и колонка «прибыль строки» через `line_profit`.

## Админка (`sales/admin.py`)

- Зарегистрированы `ProductGroup` и `Sale`.
- В списке продаж отображается вычисляемая колонка прибыли по строке.
- Для `product_group` в форме продажи включён `autocomplete_fields` (удобно при большом числе групп).
- Заголовки сайта админки переопределены (`site_header`, `site_title`).

## Запуск

Из каталога `cash_register`:

```text
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Данные вводятся в `/admin/`, отчёты открываются на главной (`/`) и `/sales/`.

## Зависимости

Виртуальное окружение репозитория (`venv/`) или установка из `cash_register/requirements.txt`: пакет **Django** версии 6.x (совместимо с ограничением `<7` в файле).
